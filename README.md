# Medieval Settlement — Three.js

A real-time Three.js sandbox for growing a **medieval settlement** on a procedural 3D landscape. On a fresh game, choose map size, topography, hydrology, forest density, regional resource abundance and variety, and world seed before generation begins. Draw dirt road networks across rolling hills, pine forests, and winding rivers — wooden bridges and graded ramps appear automatically when a path crosses water. Place production buildings to harvest timber, stone, game, berries, and fish; connect wells and woodcutter's lodges along those roads; then lay out residence zones along your roads so settlers move in over time. Homes need firewood, water, and food — road-based delivery crews haul supplies from lodges, wells, hunter's halls, forager's sheds, and fishing camps while you watch wooden carts travel the network. Assign workers from your labor pool, plant backyard gardens for local food and village gold, and keep the supply chain running before homes are abandoned. A [SpacetimeDB](https://spacetimedb.com/) Rust module runs the authoritative economy simulation; the client renders replicated state in real time. Toggle the hydrology overlay to scout well sites, use the crop-specific suitability map while laying out fields, inspect foraging nodes and quarries from map icons, and drop into first-person walk mode to explore on foot.

## Recent updates (July 2026)

- **Climate-bound charcoal clamps** — charcoal output now depends on the condition of the billet charge instead of running at an identical rate through every season. Wet spring and snowbound winter reduce authoritative clamp cycles to 80%, while drought-dried wood raises them to 110% at the cost of coinciding with the yard's highest fire danger. The same generated policy drives actual firewood consumption and charcoal output, Town Hall and workshop forecasts, input runway, next-day warnings, inspector explanations, and a bounded low-poly smoke plume, turning autumn charcoal reserves and isolated hot-yard placement into one connected planning decision without adding save state.

- **Site-dependent alluvial clay banks** — river access no longer makes every clay-pit location economically identical. Each valid shoreline exposes a stable geological yield from the same authoritative hydrology field used for placement, with regional abundance modestly shifting the result; weather and maintained iron tools then multiply that local baseline. Placement previews grade the bank before spending resources, pit inspectors reconcile geology, current ground conditions, and tools, the Town Hall averages active pits and links to the first lean bank, and one to four exposed clay strata make local quality readable on the physical model without extra save state. Forecast production, actual batch cadence, and ironwork wear share the same multiplier, so a richer but more distant pocket creates a real road-and-labor decision while lean banks remain usable.
- **Smith-dressed watermill stones and bread-chain ironwork** — grain watermills now join the same physical forge economy as farms, forestry, quarrying, clay digging, and firewood. A mill with dressing hammers and sound iron fittings grinds 20% faster, multiplying rather than replacing spring rain, drought, or frost river power; each completed milling cycle wears 0.25 ironwork, while an empty rack retains baseline output. Smithies cart a three-cycle working buffer by road, work priority, and runway, and the watermill model shows four declining tool bundles beside its grain and flour stores. Individual mill buffers, road-branch bread capacity, grain draw, output-room timing, and Town Hall ironwork demand all use each mill's actual tool condition. Weather-limited clay pits now likewise forecast only the tool wear their reduced completed work can incur. Existing saves need no migration and begin with an optional empty mill rack.
- **Physical iron farm tools and seasonal labor compression** — crop farmsteads now join the same smith-forged ironwork economy as forestry, quarrying, clay digging, and firewood. A stocked rack of wooden ploughs with maintained iron shares, hoes, sickles, and scythes makes real ploughing, sowing, and harvesting progress 20% faster; empty racks retain baseline work so an import or smithy failure cannot silently erase a crop. Wear is proportional to completed field work at 0.05 ironwork per baseline worker-day of work, not to ticks or parcel count, so dividing one field cannot evade the cost and workers away with a cart consume nothing. Smithies physically cart a three-stage working buffer by work priority and road runway, while the farmstead model shows four declining tool bundles. Farmstead, field, and Town Hall inspectors reconcile current pace, onsite and inbound stock, planned wear, whole-season reserve targets, and spring, autumn, or September labor coverage; dormant growing fields drop out of current daily smithy demand. Existing saves need no migration and begin with optional empty racks.
- **Smith-maintained winter-fuel axes** — the existing iron, charcoal, smithy, and firewood chains now meet at every staffed woodcutter's lodge. A lodge with replacement ironwork processes timber 20% faster and wears 0.25 ironwork only after a completed firewood cycle; an empty rack retains baseline output so a smithy shortage creates a meaningful winter-efficiency penalty rather than a settlement-ending hard stop. Smithies send the same physical carts along the same road branch according to player work priority, the lodge stores three ironwork on a visible tool rack, and its inspector explains stock, bonus, and wear. Town Hall firewood capacity, timber draw, tool demand, road coverage, and smithy surplus all use the same sustained-labor model, including the lone worker who alternates processing with haulage. This adds no save field or parallel inventory while making charcoal allocation, smith placement, cart travel, and autumn fuel preparation compete in one readable economy.
- **Climate-bound cured reserves and player-directed centralization** — cured provisions now follow the same deterministic seasonal environment as crops, roads, and fresh food instead of aging at one year-round rate. Spring damp and autumn humidity modestly raise loss, ordinary summer warmth raises it further, drought is the harshest condition, and winter cold halves ambient aging before each store's protection; the four normal seasons retain the previous annual-average balance. The authority and client apply the current rate to smokehouse lofts, granaries, markets, ordinary holdings, household cupboards, handcarts, and legacy reserves, while next-dawn outlooks, inspectors, food runways, and thirty-day reserve recipes expose the same pressure. The granary's existing intake switch now governs both fresh and cured surplus: disabling it leaves cured stock in the better smokehouse loft, while enabling it spends producer haulage and accepts slightly faster aging in exchange for central redistribution. This connects climate, road layout, cart contention, storage quality, and winter planning without a new inventory or save field.
- **Finite cured-food reserves** — salted and smoked provisions now age slowly in every physical store instead of becoming a permanent calorie bank. The generated balance gives smokehouse drying lofts the best retention, followed by granaries, monasteries, and markets; ordinary holdings, household cupboards, legacy reserves, and exposed handcarts lose quality faster. The authority decays building, cart, treasury-compatibility, and residence stock continuously, including during rest periods, while the client uses the same factors for household runway, road-branch warnings, and Town Hall loss hotspots. Thirty-day fallback targets now include the small quantity that will age while consumed, and production-day, salt, firewood, and pottery forecasts include losses while the reserve is being built. This keeps cured food useful for months without rewarding indefinite hoarding, adds no save fields or parallel inventory, and retains a single linear diagnostics pass at roughly 68 ms for 100,000 granaries.
- **Granary-centered cured-food reserves** — preserved provisions can no longer become stranded after the founding stockyard or a producer's household territory is full. Smokehouses serve their lowest-runway claimed homes first, pastoral holdings preserve household and cattle-manure duties, and only then does the same physical handcart move true cured surplus to the nearest road-linked granary with room. A staffed, stocked granary joins preserved-food service and redistributes three-unit ration loads after critical grain, military provisions, brewery barley, and its selected fresh-food duty; unstaffed, empty, disconnected, or fire-disabled depots promise nothing. Granaries therefore become meaningful winter reserve hubs without generating food, extra carts, or teleporting stock. Tier-three promotion still requires an operational smokehouse or pastoral producer, so an empty warehouse cannot fake a sustainable prosperity chain. Founding cleanup, road-branch runway planning, supplier previews, granary/smokehouse/livestock inspectors, and the authoritative territory cache now agree, with no save fields or extra settlement scan.
- **Stock-aware meal and bread planning** — every settlement forecast now follows the same calorie-neutral meal allocation as the authoritative household simulation. A prosperous home first schedules its current seasonal cured ration, subtracts only the amount physically present in that cupboard from today's fresh-food need, and falls back to the gross meal demand when the cured stock runs out. Town Hall bread capacity, household buffers, Sabbath readiness, full-housing growth, residence meal mix, HUD demand, and road-branch runways therefore stop charging prosperous residents for full fresh meals plus preserved food at the same time. Fresh-food runway spends only finite fire-accessible cured stores, at the bounded seasonal rate, before returning to gross demand; disconnected and fire-quarantined smokehouse stock cannot extend a branch. The settlement scan keeps the per-home calculation allocation-free, adds no save fields, and preserves the separate thirty-day all-preserved emergency reserve as a deliberate worst-case target.
- **Calorie-neutral seasonal preserved rations** — prosperous households now actually rotate cured provisions through their meals instead of letting one morsel satisfy the preserved-food expectation forever. The allocator replaces part of the same fresh-food meal rather than charging a second calorie demand, then draws deeper from preserved stock only when fresh food is short. Spring uses 0.75× of the annual-average ration, summer 0.5×, autumn 1×, and winter 1.75×; the four equal seasons still average exactly 1×, while winter becomes the design peak for promotion capacity and summer becomes the natural stockpiling window. Household runway, Sabbath buffers, Town Hall capacity, growth forecasts, smokehouse inputs, salt orders, pottery vessels, and the thirty-day emergency reserve all read the same policy. The authoritative hot path is allocation-free and resolves one million meals in roughly 60 ms under the native debug benchmark.
- **Road-matched winter preservation reserve** — the Town Hall now turns prosperous households' emergency preserved-food fallback into a concrete thirty-day preparation target instead of presenting it as ordinary daily consumption. The ledger matches each occupied tier-three home to preserved stock and incoming carts on its own road branch, excludes fire-quarantined stores, identifies the weakest branch, and forecasts completion from staffed same-branch smokehouses. Every missing unit resolves back into exact fresh food, firewood, Adriatic salt, and pottery-vessel requirements; owned salt and pottery reduce those needs locally, while remaining salt is expressed as whole import lots and approximate current-rate gold exposure with warnings for branches that lack standing orders. The planner is a linear, read-only view of the existing physical economy, adds no save fields, and makes kiln priority, broker funding, cart routing, workshop placement, and autumn stockpiling part of one visible decision.
- **Physical household pottery economy** — prosperous households now require a slow replacement flow of cooking, serving, and storage vessels instead of letting the clay chain terminate almost entirely in export. A staffed potter's kiln claims stocked tier-three homes on its own road branch, sends visible pottery carts to the lowest-runway cupboard first, then releases its one cart to smokehouse packing buffers and market export. Tier-three upgrades require an operational potter route; residence, kiln, and Town Hall ledgers expose cupboard runway, supplier distance, territory, next cart, total demand, and road-matched prosperity capacity. Established tier-three saves receive one temporary cupboard buffer, while new homes must be supplied physically. This reuses the existing pottery icon, build card, procedural kiln and stock models, vessel cart load, commodity ledger, and additive residence-need rows instead of creating a parallel ware system.
- **Player-directed pottery cart priority** — every potter kiln can keep the save-compatible household-wares-first order or stage preservation vessels first. Homes-first protects prosperous cupboards before serving smokehouses; preservation-first protects salted winter-food throughput before replacing household breakage. Either mode immediately falls through when its first local duty has no reachable shortage, and export always remains third, so a nearby broker cannot consume the kiln's one physical cart while either local chain is exposed. The kiln inspector states the exact order and previews the destination selected by that same policy.

- **Deferred settlement ledgers** — the complete inspector and Town Hall reporting graph now leaves the initial application chunk and downloads through the existing settlement-presentation boundary while terrain generation is already under way. The initial production entry fell from 1.735 MB to 990 KB raw and from 493 KB to 310 KB gzip without removing any economic forecast, model, or interaction. A production-build regression test proves the inspector stays outside the entry chunk and enforces 1.10 MB raw / 350 KB gzip startup budgets as future systems grow.

- **Actionable settlement welfare ledger** — hunger, recovering malnutrition, sickness, household herb reserves, comfort-driven migration pressure, mortality, physical burial carts, grave capacity, and vacant-home decay now resolve into one shared settlement summary instead of remaining scattered across individual inspectors. The HUD appears only for a real watch or critical condition and distinguishes starvation, untreated illness, blocked burial, and resettlement-blocking decay; the Town Hall retains the full accounting and opens the highest-risk occupied home or most decayed vacant structure directly. Grave reservations are deducted from open capacity while carts are moving, bodies remain disease risks until the empty cart reaches the home, and sick residents are reported as unavailable labor rather than abstract population loss. The summary is folded into the existing provisioning residence pass rather than adding another snapshot scan; its standalone projection processed 100,000 homes in about 12 ms.
- **Household-first physical fuel economy** — woodcutter lodges and village storehouses now finish their real household cart duty before offering any remaining firewood to bakeries, breweries, smokehouses, charcoal clamps, or pottery kilns. Surplus dispatch is source-side and deterministic: staffed workshops compete by player-set work priority, then lowest recipe-cycle runway, road distance, and stable identity, so table update order can no longer decide which production chain stays hot. An idle workshop cannot sequester communal fuel, while each processor's output-stock target controls whether it stages one, two, or three firewood cycles. Lodge and storehouse inspectors preview the next industrial claim and active destination. The Town Hall now separates cupboards, ready distributor yards, hot-workshop buffers, live carts, inactive stock, and fire-quarantined stores; it also compares full-winter hearth demand plus installed industrial burn against sustainable staffed-lodge output and timber draw on every road branch. Existing saves need no migration, and target selection remains a single bounded scan.

- **Legible industrial fire planning** — the severe accident risk already carried by charcoal clamps and smokehouses, and the elevated risk at smithies, pottery kilns, fuel-heavy workshops, barns, breweries, and granaries, now becomes a layout decision before construction instead of a hidden coefficient. One generated balance table feeds both the Rust ignition authority and client forecast. High-risk placement previews and selected buildings draw a terrain-following 26 m spread ring: green for a staffed, supplied well response, amber for an in-range but unstaffed, dry, or busy well, and red for no ready coverage. Placement and inspector readouts report current stored-fuel amplification, operational buildings and occupied homes exposed inside the ring, the selected well route, and estimated first-bucket arrival. A busy nearest well now yields the emergency to a farther ready responder instead of blocking the entire response. This adds no save field or periodic settlement scan, and the derived planning pass remains near 14 ms for 100,000 buildings.
- **Directional, uncertain raid warnings** — the exact incursion schedule is no longer exposed as a guaranteed HUD timetable. Ordinary scouts and travelers may miss an approach, although larger raiding parties are progressively harder to conceal. A staffed watchtower reliably detects only the actual map-edge lane reached by its effective sight radius: one lookout has a smaller detection footprint, two have the full radius, an outward tower provides more lead time, and a tower on the wrong side of the map provides none. The authority persists the planned side so a reported northern approach cannot become an eastern spawn if stored wealth shifts before contact. A successful report raises a toast with source, direction, party size, and an approximate countdown; an undetected raid instead raises an immediate contact alarm. Likely-target markers remain hidden until a real report or physical contact.
- **Committed cart round trips** — work hours and an observed Sabbath still block every new ordinary-cart departure, but a crew already on the road now finishes its outbound leg, unloads, and returns home instead of freezing at 20:00 and resuming in place the next morning. Fire response retains its emergency exception, while a live raid still recalls exposed outbound carts and lets returning carts complete their retreat.
- **Physical fire displacement** — a fire-disabled workplace no longer leaves its visible crew forging, harvesting, drilling, or standing inside the burning site while the authoritative economy is paused. The same rostered people put away their tools, evacuate over the real local route to their household or founders' camp, remain inspectable as fire-displaced, and commute back only after recovery; their labor assignment is not silently freed. Residents who are actually home leave the house for deterministic assembly places beyond its footprint, while household members already working at a safe site keep producing so presentation does not invent a server-side labor loss. During a frontier alarm, a burned guard post no longer grants defense-duty immunity and a burned refuge cannot receive a rally. Fire-disabled homes immediately lose ordinary hearth smoke and window light, and their residents physically return after recovery. The routine adds no save fields and remains bounded by the existing 1,024-agent crowd ceiling.
- **Player-directed loom inputs and fibre routes** — every weaver can now use the legacy automatic recipe choice, prefer a ready wool cycle, or prefer ready flax plus hauled water. Work priority remains the strongest cart override; among equal-priority active looms, sheep-holding and farmstead carts now replenish a matching specialization before the neutral Auto pool and the opposite fallback, while covered working buffers return to nearest-route overflow. Flax-first looms with fibre physically staged also enter the well's household-first industrial queue ahead of neutral equal-priority workshops, while wool-first looms yield contested water; this replaces update-order-biased target pulls with the same one-pass source-side arbitration used by bakeries and brewhouses. The alternate recipe remains a production fallback so a stocked workshop does not idle, and authoritative dispatch, client route previews, production, Town Hall input-runway forecasts, well and workshop inspectors share the policy. Wool-first saves planned flax for later; flax-first turns field fibre and well/cart capacity into cloth while preserving the annual fleece clip. Existing workshops default to automatic selection, route arbitration stays one-pass, and all fibres, water, cloth, household deliveries, and export hauls remain physical.
- **Inspectable, fordable live combat** — every replicated raider and defender can now be selected in the ordinary person inspector to read their current objective, health, equipment, readiness, captured stores, and exact activity instead of inferring the battle from an aggregate alert. Combat visuals use the existing road-surface sampler while taking a bridge, so fighters no longer appear below its deck. Rivers remain intentionally fordable cross-country terrain for both sides, reflecting the settlement fantasy of shallow Gorski Kotar and Kupa-valley crossings: a river or delta cannot become an invulnerability wall, while roads and bridges retain their faster coordinated-route advantage.
- **Audible physical melee** — close inspection of a live fight now carries sparse, generated polearm impacts, shield contact, equipment movement, and nonverbal human exertion from the combatants' actual map positions. Approaching, retreating, downed, and ordinary-duty agents remain silent; distance attenuation and the strategic-zoom cutoff keep the settlement soundscape readable, while pausing or ending the engagement stops in-flight sounds immediately. One source per active raider, a twelve-source ceiling, shared one-shot pools, and global cadence limits keep the pass bounded even when many defenders answer the alarm.
- **Physical raid contact and exact loot** — every building, cottage, treasury seat, and refuge now receives a deterministic exterior assault point on the raider's approach side instead of drawing attackers through its model center. The authority derives building envelopes from the shared placement catalogue, uses the authored cottage radius, keeps moving carts on their live position and broader interception radius, and ends cached incursion routes at the same physical contact. Raiders visibly strike stationary holdings throughout forced entry, while moving-cart plunder remains a rummaging action and guards may leave roads to intercept anywhere. When several raiders share a target, complementary carrier shares now reproduce the declared loss budget exactly if all succeed instead of compounding below it; only agents that actually finish contact carry anything away. Interrupted or reconnected wounded guards also return their issued polearm to the rack only after physically reaching their guardhouse.
- **Authoritative on-map frontier combat** — due incursions now spawn a bounded party of replicated raiders at a deterministic map edge instead of applying an off-map loss roll. Each raider owns a live position, target, health, combat state, and carried-loot bundle; each responding guard is backed by one armed slot in an actual guardhouse roster and temporarily replaces that worker's ordinary crowd figure. Roads are a faster preferred leg, never rails: guards and raiders cut across country to intercept, chase carts, fight, reach an active attack, or answer an unlinked holding. Both sides physically close distance and exchange melee damage, using the villagers' authored movement and weapon-swing animation with the existing audited CC0 spear. A raider must reach the exact building, home, treasury seat, or moving cart and spend four local seconds looting before its authoritative stock can change; arson is possible only after that contact, and carts cannot be burned as structures. Stolen commodities travel back out on the raider, while an intercepted carrier drops the exact bundle into a recoverable map stockpile. Capable raiders who are advancing, fighting, looting, or physically retreating directly govern refuge rally and the settlement-wide emergency stop. New ordinary-cart departures cease, carts caught outbound or unloading reverse along their physical route with the same crew and exposed cargo, already-returning carts keep moving, and fire responders continue; pursuing raiders still chase the cart's live position and can plunder only after contact. If a pursued cart reaches home first, the same live pursuit transfers to its receiving store before the cart row clears; its loss fraction is rescaled to the remaining cart value so arrival cannot despawn an attacker or expose an unrelated warehouse windfall. Combatants and carts advance on the same five-heartbeat physical cadence at the selected game speed instead of making battles wait on sparse calendar/economy steps. Once the last hostile escapes or falls, ordinary work, carts, migration, and household settlement resume while guards continue their visible return and recovery. Survivors must physically escape and guards must walk home before the final report is recorded. Peaceful worlds clear the combat lifecycle entirely, simultaneous multiplayer raids are owner-isolated, party size is capped at twelve, and the hot movement/combat policy remains deterministic and benchmarked.
- **Persistent guard casualties** — a guard downed in physical combat no longer disappears into an abstract result or returns to duty at the next update. That same replicated roster agent remains on the battlefield, limps back to its source guardhouse after the raiders are gone, and recuperates visibly for three to five in-game days; a well-supplied, paid company recovers faster. Its exact roster slot cannot muster again, be released into another workplace, or be erased by demolishing or reconstructing the guardhouse. Wounded guards continue to consume company provisions and wages, the authoritative district forecast subtracts them, and the HUD plus guardhouse ledger distinguish fighters in the field, evacuation, on-site recovery, fit strength, and remaining recovery time. Recovery reuses the existing combat-agent row and state tick, so old saves need no migration or parallel casualty table.
- **Player-directed company muster posts** — a completed guardhouse can now keep the save-compatible nearest-watch order or be bound to one chosen completed watchtower. An explicit order lets a rear company reinforce a threatened district without rebuilding the post, but its real road length and seasonal travel penalty still reduce timely strength; if that watch is unstaffed, burning, or cut off, the company waits rather than silently teleporting to a safer district. The guardhouse ledger previews every post from one batched road tree, exposes the active order and failure state, and the selected route, raid forecast, visible spear muster, and authoritative raid outcome all consume the same assignment. Demolishing the post safely returns its companies to automatic duty. One additive zero-default building field preserves existing saves and adds no new unit, commodity, or per-tick scan.
- **Visible road-linked guard musters** — when raiders are reported during the April–October campaign season, every equipped guardhouse worker now leaves ordinary drill, follows the same road-linked watch claim used by the raid forecast, and forms a deterministic spear line clear of the tower ladder. Several companies answering one watch extend the formation instead of overlapping; watchmen remain on the gallery, while unarmed, disconnected, or fire-disabled companies do not falsely appear in the response. Guards return to their guardhouse when the alert clears. The forecast and crowd presentation reuse one batched muster plan—one road tree per company—so no route is solved twice, and the change adds no save field or new asset beyond the existing audited CC0 hand-rigged spear.
- **Visible civilian refuge rallies** — once raiders are reported during the April–October campaign season, rendered members of every assigned household leave ordinary routines, follow roads and yards to their claimed palisaded refuge, pass through its open gate, and occupy one of 32 deterministic places inside. They return home—and workers resume their normal commute—when the alert clears; winter pauses and peaceful worlds never trigger a rally, while defense workers remain on duty rather than taking civilian places. The raid forecast and crowd presentation reuse one capacity assignment instead of sorting the settlement twice, add no save state, and make overlap, overcrowding, fire loss, and exposed homes readable directly on the map.
- **Capacity-bound civilian refuges** — each compact palisaded enclosure now holds at most 32 residents instead of sheltering an unlimited village. Warned families claim places as whole households at their nearest active refuge, then try an overlapping second enclosure when the first is full; anyone who still lacks room remains exposed, and a burning refuge removes its capacity immediately. Refuge and Town Hall ledgers show demand, assigned places, and the remaining gap, while the server and client share the same deterministic rule. The assignment uses spatial buckets plus one bounded candidate sort, adds no save field or artwork, and remains comfortably bounded across 100,000 households.
- **Road-linked watch districts** — each supplied guard company now reinforces only its nearest staffed watchtower over an exact road route, so a strong central muster can no longer defend a disconnected satellite holding by virtue of a settlement-wide guard total. Incursion targeting, portable-stock loss, arson pressure, frontier markers, the HUD, and the Town Hall all evaluate the guards that can answer each physical holding; burning towers or companies immediately remove their local protection, and weather-softened roads weaken long musters. Overlapping warning areas may combine genuinely distinct companies, route ties are stable, and the authority and client each reuse one batched road tree per company. The rule adds no save field and keeps the 10,000-holding client projection comfortably bounded.
- **Exclusive parish-monastery territories** — every household now belongs to its nearest completed, fire-safe Pauline monastery only when it already lies in a staffed road parish and the monastery is chapel-linked within its physical coverage. Overlapping houses no longer receive duplicate feast benefits from whichever monastery row happens to run first; each observance serves only that monastery's claimed homes, while a burning chapel or monastery immediately suspends the link. The authority caches one exact territory per settlement substep and reuses it for residence growth, recovery, chapel attendance, and feast recipients; the Town Hall builds the same forecast in bulk. This replaces repeated household-by-monastery Dijkstra searches with one batched road tree per landmark, adds no save field, and makes monastery placement a legible road-topology decision.
- **Organic four-corner fields and pastures** — farm and livestock holdings now trace genuinely flexible convex parcels corner by corner instead of expanding a forced rectangle from one baseline. Polygon area and centroid math are authoritative on both client and server, existing rectangular saves retain their exact yield, and skewed or elongated fields pay a modest visible shape-efficiency cost in both labor and harvest. The live preview shows the open boundary before the parcel closes, rejects crossed or concave outlines, and samples a bounded 5×5 grid across the whole parcel so a field cannot bridge open water or a quarry between apparently safe corners. This unlocks tighter fitting around roads, slopes, rivers, buildings, and neighboring land without a schema change or simulation-tick work.

The marketplace inspector names the exact commodity mix, total queue, and current gold value, while inventory bands stay out of collider updates and add no save fields or simulation work.

Their inspector names the exact full store and missing room, making export policy, household collection, monastery hospitality, roads, and seasonal cart timing genuine production constraints. Threshing sheaves, apiary baskets and honey jars, and vineyard grape baskets and wine casks now fill and clear from authoritative onsite stock in coarse map-readable bands. The enlarged free pool then fills supplied, below-target sites by high, normal, and low priority with fair sharing inside each tier. Enabling performs one conservative recall-then-deploy rotation immediately; unlike the manual call-up, automation will not pre-staff an input-empty workshop. Salted smoking, pottery firing, charcoal burning, and iron smithing must have every physical recipe input on site or en route before the steward commits scarce labor. A unified Dawn labor review projects seasonal, production, and construction stages in authoritative order against one evolving labor pool, using the next day's month at calendar boundaries and linking to the first crew change. Existing saves remain manual.
- **Daily construction labor steward** — a staffed Town Hall can optionally turn construction holds and urgency tiers into an ongoing queue policy. At each new calendar day it releases builders only from sites that cannot progress and have no material cart approaching, then fills immediately productive urgent, normal, and low sites with fair sharing inside each tier. Enabling performs one rotation immediately, inbound-waiting crews remain assigned, and existing saves stay manual. When multiple stewards run, time-critical seasonal work is reviewed first, target-governed production second, and construction last; ordinary ticks return before any steward settlement scan.
- **Daily seasonal labor steward** — a staffed Town Hall can optionally review seasonal crews at each new calendar day: dormant farm, forage, fishing, apiary, and vineyard labor is recalled first, then free villagers fill currently active sites using the existing staffing priorities and fair within-tier rotation. Enabling the policy performs one review immediately; removing the clerk pauses it; manual control remains the save-compatible default. The ordinary simulation path returns before scanning settlements on non-boundary ticks.
- **Prosperity throughput planning** — the Town Hall now converts staffed smokehouse, brewery, weaver, and potter capacity into the number of prosperous residents the settlement can sustain, names the limiting chain, and compares current occupancy with the full tier-three housing pipeline. Before promoting a tier-two household, its inspector shows both the occupants' immediate daily load and the fully occupied house's demand. The forecast is advisory rather than a hard gate, so a player may still accept a temporary shortage; it reuses the existing read-only production scan, adds no save fields, and runs only while the relevant inspector is open.
- **Annual textile planning** — sheep shearing now waits until a holding can store the entire clip, so a nearly full loft no longer discards most of an irreplaceable yearly fleece. The Town Hall connects current flock health and supply, holding labor, full-clip storage room, moving wool and cloth carts, installed loom capacity, prosperous-house consumption, and exportable annual surplus in one textile ledger. Its physical view pairs each projected clip only with loom capacity and current prosperous-house demand on the same cached road branch, so remote fleece, idle satellite looms, and disconnected household claims remain visible instead of cancelling one another settlement-wide. Current reserve runway counts only occupied tier-three cupboards, cloth at a stocked staffed weaver on that branch, and carts already bound to those homes; treasury, export-market, idle-workshop, and disconnected stock remains owned but cannot promise household service. Home and Town Hall runway labels now share the authoritative 14-hour daytime consumption window. Missed, unstaffed, unhealthy, storage-blocked, topology-stranded, and presently unserved branches remain distinct, with direct inspection of the first exposed home or holding.
- **Priority construction crew rotation** — a staffed Town Hall can release builders only from sites that cannot make progress and have no material cart approaching, then deploy available workers to immediately productive sites. Urgent construction fills before normal and low priorities, while equal-priority sites share labor round-robin. Crews waiting on inbound carts remain assigned and founders’ reserves count as productive work. The order stays available manually, while the optional daily construction steward repeats that exact safe rotation after the player opts in.
- **Target-governed production crews** — mills, granary bakeries, breweries, smokehouses, weavers, charcoal yards, smithies, potters, quarries, and clay pits no longer need to strand full crews when their output is capped or their yard cannot accept more material. A staffed Town Hall can recall surplus labor while retaining one dispatcher for finished stock or an active cart, then separately deploy free workers to eligible sites by staffing priority and fair within-tier rotation. The optional daily production steward conservatively automates that loop only for supplied or recovering sites, turning output targets, material storage, and complete recipes into ongoing labor-allocation decisions while leaving deliberate pre-staffing to the player.
- **Settlement haulage ledger** — the Town Hall now turns authoritative active cart rows into a readable logistics workload: outbound, unloading, and empty-return phases; committed haulers; cargo still aboard; busiest commodity; emergency fire responses; measured one-way road distance; and remaining hauler-time. The longest active haul can be selected directly, opening its moving worker panel and highlighting the remaining route so expensive mountain-road layouts are visible instead of hidden behind a cart count. The summary reuses the workforce ledger's existing linear trip pass, performs no inspector-time pathfinding, and adds no save fields or simulation work.
- **Three-year cyclic crop-rotation planning** — every field can schedule an explicit Year 1 → Year 2 → Year 3 cycle across mountain rye, spring oats, barley, fibre flax, wheat–rye maslin, and worked fallow. Field, farmstead, and Town Hall ledgers project each later year's crop area, seed demand, grain and fibre output, and area-weighted soil trajectory; they also show how much land has a complete cycle and identify the weakest Year 3 field. Current cattle manure feeds the first transition while future manure is deliberately excluded instead of promised, and paused land cannot recover fertility without being worked. Older fields preserve their prior behavior by repeating Year 2 until the player deliberately schedules a third slot.
- **Crop-year grain allocation** — the Town Hall now reconciles bread grain in treasury stores, buildings, and moving carts against three protected claims: field seed, local winter fodder, and central granary floors. It then exposes the genuinely discretionary stock and its runway at current bakery and linked/unlinked monastery capacity; brewing barley is tracked separately and cannot consume those reserves. A 120-day crop-year balance compares the labor-covered September harvest with sowing, winter herd, and processing commitments, flags the first exposed holding or granary, and excludes imports explicitly. Its grain-cart ledger also counts operational processors by high, normal, and low work priority: farm and granary carts restore every higher tier before comparing cycle runway, road length, and stable building order inside that tier. A separate standing-order ledger shows completed granary and physical marketplace seed already included in owned stock, future lots still due, current-rate treasury exposure, labor/road/frontier-queue blocks, and the current holding gap those sources could recover on matching road branches without double-counting them in the crop year. The projection is read-only, linear in buildings and carts.
- **Settlement construction ledger** — the Town Hall now turns every existing building site into one readable queue: urgent/normal/low/held mix, assigned builder capacity, remaining builder-days, delivered timber and stone, material still covered by the founders' reserve or waiting at stores, cargo already on carts, and genuinely uncovered demand. Its physical reservation view matches road-required claims only with completed material sources on the same branch, separates topology-stranded earmarks from settlement-wide scarcity, and preserves the global hauling ceiling for buildings designed to operate off-road. It identifies and opens the highest-priority site waiting on builders, road access, unreserved material, a reachable source, or a hauler, while sites already building or receiving supplies stay out of the warning path. The summary is a linear read-only projection of the existing queue, so it adds no save fields or background simulation work.
- **Readable frontier deployment** — selecting a staffed watchtower now shows its true one- or two-person warning radius instead of always showing full coverage. Selecting a guardhouse traces the exact road route to the staffed watchtower that musters it; green, amber, and red route feedback makes full-strength, delayed, and weak response layouts legible before a raid, and the guardhouse ledger can jump directly to the linked post. Current ground conditions turn that physical route into a time-equivalent response distance, so compact defense branches can stay fully responsive in spring rain while marginal long routes visibly lose strength.
- **Smaller startup script** — villager, delivery-cart, fire, residence, field, pasture, fencing, and livestock presentation code now downloads and parses behind terrain generation as one coherent chunk. It is still ready before the first synchronized settlement frame, reducing entry-script work without introducing visual pop-in.
- **Peaceful or contested frontier worlds** — world setup now offers a raid-free settlement mode or configurable enemy pressure. Frontier settlements can staff road-linked hillside watchtowers, read seasonal threat and coverage in the HUD, and maintain paid guard companies whose readiness grows out of the settlement economy. Guard companies answer the nearest staffed watch by road: short signal routes muster the full company, distant routes contribute less effective strength, and disconnected companies cannot reinforce a warned district.
- **Standing frontier procurement** — each contested-world marketplace can remain manual-only or keep 6, 12, 24, or 48 imported iron heads and fittings in local stock. Staffed road-linked brokers buy one six-unit lot at current regional rates whenever it fits below target, consuming local market-coffer gold and normal trade-desk cooldown before carpenters haul the fittings onward. Existing saves default to manual-only procurement.
- **Physical market working cash** — imports in physical-economy settlements spend only coin held in that marketplace’s visible coffer. Players choose a 0, 16, 32, or 64 gold reserve; free haulers carry shortages from the founders’ chest or Town Hall, brokers sweep only surplus receipts back, and residence-upgrade coin remains protected. This makes import capacity compete with wages, improvements, roads, and cart labor instead of drawing from a disembodied treasury.
- **Granary intake planning** — each staffed granary can shelter fresh-food surplus to 25%, 50%, 75%, or 90% of capacity. Lean branches preserve nearby household turnover and cart time; deep reserves reduce spoilage and prepare for winter while leaving bakery headroom. Existing saves retain the former 75% target.
- **Food-loss diagnostics** — the Town Hall now identifies the treasury, worksite, or household losing the most fresh food and can jump directly to that store. The same ledger totals configured granary intake targets, collection headroom, active staffing, and food sitting above target, so preservation policy and cart bottlenecks are visible at settlement scale.
- **Distributed material depots** — every village storehouse can collect timber, stone, and firewood to separate 25%, 50%, 75%, or 100% capacity targets. Small branch caches leave overflow carts and producer stock available for other depots; deep caches shorten nearby construction and winter-fuel routes. After household fuel duties, the fullest blocked producer claims the nearest compatible idle depot, making road layout decisive without hidden construction-order bias. Targets cap incoming collection only, so construction and households can still draw them down. The Town Hall totals stock, target headroom, and staffing across the depot network, while existing saves retain the former fill-to-capacity behavior.
- **Owner-scoped placement clearance** — buildings, burgage plots, fields, and pastures now test overlap only against the current settlement's indexed rows. Invisible structures left by another local browser identity can no longer block construction or exhaust valid work extents, while natural terrain, rivers, forests, and quarry-site rules remain authoritative.

- **Full-day simulation pacing** — server-authoritative Pause/1×/4×/8× controls provide 5-minute, 75-second, and 37.5-second days. The full day/night cycle, movement, logistics, production, ecology, weather, and calendar stay synchronized, while Pause hard-freezes the world.
- **Seasons and visible weather** — the fixed calendar drives planting and harvest windows, winter heating, seasonal ecology, rain, snow, drought lighting, fog, and atmospheric color.
- **Structural fires, firefighting, and recovery** — lightning and workplace accidents can start spreading fires; staffed wells dispatch physical bucket responders, and damage remains after the flames are out. Once a 12-second cooling period passes, repairs cost a damage-scaled share of the structure's timber and stone. Destroyed buildings reuse their foundations and return to the normal material-cart and builder pipeline at 70% cost, while homes are restored immediately and a rebuilt household must be resettled. A road-linked operational carpenter trims reconstruction timber by 10%, but a fire-damaged workshop grants no bonus until repaired.
- **Richer vegetation** — cultivated SeedThree orchards, wind-animated flowers, textured rose blossoms, and raspberry foliage cards replace earlier placeholder vegetation. Backyard lawns now use the world terrain instead of separate green slabs.
- **Faster startup and lighter UI assets** — generated terrain is cached and prepared off the main thread, detailed vegetation is deferred until the world is playable, and build-menu artwork loads lazily from compressed cards.

## Setting & visual direction

**Gorski Kotar, Croatia — circa 1500–1600.** The default sandbox is a wet, wooded highland in the Dinaric Alps: beech–fir valleys, karst ridges, limestone hamlets, and seasonal trade with Kvarner. Regional market goods, forest species, and building materials all lean into that slice of Croatian history. You are free to retarget the game to another region or era — treat this as a starting point, not a hard constraint.

**Build menu cards** use a **Croatian naive art** style — folk painting with flat color, bold outlines, and charming asymmetry. Examples live in `public/assets/ui/build-menu/`.

**3D buildings and residences** follow the shared [building visual language](docs/design/building-visual-language.md): grounded Gorski vernacular, limestone-and-timber construction, and silhouettes readable at settlement zoom. The chapel mesh is the reference implementation.

**Generating new assets?** Before asking an LLM or agent to create buildings, menu illustrations, or textures, point it at `docs/design/building-visual-language.md` and the existing art under `public/assets/` so output stays consistent. To shift the whole aesthetic — different country, period, or illustration style — update that document first (or ask your agent orchestrator to do that), then regenerate art and meshes against the new brief.

## Features

### Road building

- Interactive point-by-point road drawing projected onto a 3D terrain heightfield.
- Terrain projection so roads follow hills, slopes, and ground variation.
- Snapping to existing road nodes and road segments.
- Automatic edge splitting when new roads connect to existing segments.
- Wheel-adjusted curvature per segment (`Ctrl + scroll`).
- Junction classification for endpoints, bends, T-junctions, cross-junctions, and complex junctions.
- Junction and endpoint cap meshes that blend road ribbons into clean intersections.
- Textured medieval dirt road materials with irregular blended shoulders.
- Live road preview while drawing, plus selection and delete with confirmation popup.
- Undo last placed point, undo last committed change, redo (`Ctrl+Y`), and full draft cancel.
- Terrain road-wear blending that tints grass to packed dirt along committed road corridors.
- Automatic river bridge generation when a road crosses water — graded approach ramps, elevated deck, and instanced support posts.
- Wood-log bridge deck material blended onto the road ribbon via a per-vertex `bridgeBlend` attribute.
- Bridge preview tint while drawing, plus placement validation that rejects spans wider than the max bridge length.
- Rock collision checks that block roads through scattered forest and river-shore boulders.
- Road-network connectivity for gameplay — buildings and residences must be within road-path distance for access, mill→lodge timber routing, and lodge/well/food-supplier delivery.

### Economy & settlement

- **Frontier security** — contested worlds begin generating pressure after the settlement reaches eight people. April–October incursions choose a bounded pressure-scaled set of the richest exposed stores, treasury reserves, moving carts, and households, then materialize people at the map edge. Raiders can steal only from a holding they physically reach and loot, can ignite at most one contacted structure, carry the removed goods during their retreat, and drop that exact bundle for recovery when a guard downs them. Armed, supplied guardhouse workers answer their assigned staffed watch district as replicated defenders, physically intercept attackers, exchange melee damage, and return to their post after surviving raiders escape or fall. The ordinary well, bucket-cart, fire-spread, damage, repair, and reconstruction systems handle any resulting fire. Watch coverage provides warning and a lower exposed-loss share rather than immunity; company placement, weapons, provisions, roads, and player-selected muster posts determine whether real guards arrive in time. Each frontier report names the current likely targets, bounded amber-to-red world markers identify them as pressure rises, and the HUD reports live combatants and downed agents. Periodic forecasts still build one coarse-cell watch index and classify candidates in one holding pass, while the live party is capped to keep per-tick combat bounded. Peaceful worlds remain fully raid-free and contain no combat agents.
- **Raid-vulnerable reconstruction stores** — beginning fire recovery no longer makes retained food, textiles, armaments, or money disappear from the frontier economy. Stock-bearing worksites remain valid raid targets and contribute to warning coverage until their goods are moved or lost, while empty new construction sites remain irrelevant and unfinished watchtowers or guardhouses provide no defense. The rule derives entirely from existing building state, so old saves need no migration.
- **Frontier watchtower** — a road-linked hillside defense staffed by up to two watchmen drawn from real settlement households. They commute to the exterior ladder and visibly keep separate sight lines from the open raised gallery during working hours. The first watchman provides a reduced warning radius and the second reaches the full 190 m extent, turning labor allocation and settlement layout into explicit protection tradeoffs. Live reports show the ready guards required at current coverage, likely targets, and projected loss severity.
- **Frontier guardhouse** — available after a watchtower is complete. Up to six paid guards leave the general labor pool, require one carpenter-made polearm each, consume food and treasury wages every day, and lose readiness when either supply fails. Each guardhouse can be given low, normal, or high company priority. Higher tiers claim scarce carpenter-made polearms, routine provisions, and treasury wages before lower tiers; equally important companies receive weapons by lowest armed share, then shorter road and stable building order, while payroll uses stable company order. Both the guardhouse and Town Hall forecast the next day's funded wages. Each carpenter can hold 0, 2, 6, 12, or 24 finished polearms; a zero target preserves timber and imported ironwork while retaining cartwright and construction support, and new workshops default to one six-person company's reserve. Carpenters issue only one weapon per assigned guard and keep surplus at the workshop, so an inactive or partial company no longer drains an entire armory. Unarmed companies also do not warehouse provisions they cannot consume. Every armed company can hold a lean, standard, or deep ration reserve of 3, 6, or 12 food per guard; existing saves retain the former six-unit target. Lean policy releases perishable food and carts to households, while a deep reserve can bridge a disrupted frontier route at the cost of spoilage exposure and a larger plunderable stock. Their routine provision carts take only stock above local household delivery reserves, while staffed granaries source-dispatch an emergency cart to the armed company with the lowest food runway once it drops below three days. If grain processing is also critical, the lower relative runway wins before route distance and stable building order. Military upkeep therefore creates a real surplus-production and cart-capacity requirement instead of silently starving the nearest homes. Warning coverage improves their ability to muster, and rain or cold-season ground conditions make long watch routes respond as if they were farther away, so lookout placement, road layout, seasonal planning, and guard upkeep reinforce each other instead of becoming separate combat systems.
- **Palisaded refuge** — after completing a guardhouse, a contested settlement can invest 72 physically hauled timber and 30 stone in a compact wooden-and-earth civilian enclosure. Its 68 m rally catchment shelters only occupied households that also receive a staffed-watch warning: those families can carry people and household coin inside, reducing that household's raid loss by 40%. Building inventories, loaded carts, workshops, and Town Hall treasury remain exposed where they are physically stored, so the refuge cannot teleport a granary into safety or replace paid guards. Placing homes where watch and refuge circles overlap creates a real defensive neighborhood; an unstaffed or burning watch removes warning, and a burning refuge suspends shelter. The authoritative and client forecasts use coarse spatial buckets, keeping 1,000 watches, 1,000 refuges, and 100,000 holdings near 30 ms in the parity benchmark without adding save fields.
- **Road-matched specialty export ledger** — the Town Hall now follows physical ale, honey, wine, and cloth from completed producers through loaded carts into each market's broker queue. Cached road branches expose source stock with no completed market route, full destination stores, unstaffed or fire-blocked producers, returning source carts, and markets whose sole receiving slot is occupied. The broker side separately reports price-floor holds, unstaffed or roadless desks, manual transactions occupying the sole broker, current free-broker throughput, and the slowest active queue. Local household and enabled monastery claims retain their authoritative priority before export, and unstaffed markets may still receive cargo exactly as the simulation allows—creating visible storage backpressure until the player assigns brokers. Reconnecting a road branch immediately makes compatible source stock routable. This read-only ledger adds no save state or tick scans and completes its 100,000-building / 200-branch regression in roughly 140 ms.
- **Road-matched armament ledger** — in contested worlds the Town Hall now audits the whole imported-ironwork → carpenter → guardhouse chain by cached road component instead of treating every owned weapon as interchangeable. It separates polearms already issued, carts actually approaching an underarmed company, finished reserves at staffed carpenters on the same branch, and weapons stranded in treasury, excess company stores, idle workshops, or disconnected armories. A second forecast counts only polearms whose timber and ironwork are already at or approaching their selected carpenter, exposes remaining raw-material claims and connected source stock before cart contention, and links directly to the weakest company. Reconnecting branches immediately restores the physically reachable reserve. The read-only pass adds no save state or path solves and remained near 102 ms for 100,000 buildings across 200 branches under the full test load.
- **Seasonal provisioning forecast** — the settlement HUD turns aggregate food, household fuel, and paid-guard wages into days of runway. Food runway includes current season/drought spoilage across treasury, buildings, and household stores; a separate local-delivery buffer reports how many homes actually hold a workday of food, water, and provisions plus enough firewood for the nightly no-cart interval. The Town Hall ledger exposes the need-by-need shortfall, military upkeep, and household-by-household Sunday readiness when Sabbath observance is active. Its processing ledger converts staffed mill, granary, brewery, smokehouse, and weaver labor into supplied daily capacity, identifies the mill/bakery bottleneck, and reports the grain, water, firewood, fresh-food, and wool inputs needed to sustain that output. Per-workshop input runway includes only loaded carts whose authoritative route timing gets them unloaded before existing stock is exhausted; a late cart remains visible but does not conceal the intervening production stop. Its field ledger also rolls every holding into one September harvest, onsite seed, spring-oats, and autumn rye/fallow plan while retaining per-holding labor and seed shortfalls, so surplus at one farm cannot hide an exposed field group elsewhere. A central-granary line separates protected strategic grain from processor/trade surplus. Guard readiness is audited separately against polearms and food physically stored at each guardhouse, so a full remote granary can no longer hide the first company about to lose readiness. Autumn and winter surface a 30-day frost-fuel target. Forecasts assume no new production and explicitly warn that disconnected stock can still be inaccessible.

- **Workforce planning** — the Town Hall separates permanent jobs from temporary builders, groups staffed capacity into provisioning, materials, haulage, civic, and defense sectors, and counts workers currently committed to cart runs. Its full-housing projection shows whether the current burgage stock can staff every permanent post or whether the settlement should build more homes before expanding industry. Empty worksites can be opened directly from the ledger. Every operating worksite can also be marked low, normal, or high staffing priority: if abandonment or fire recovery reduces population, temporary builders release first, followed by low-priority jobs, while essential high-priority services retain workers longest. The same visible choice prioritizes scarce grain carts at watermills, breweries, and monasteries, plus industrial well-water carts at breweries and granary bakeries. Untouched buildings remain normal; a site deliberately built at low or urgent priority carries that intent into operation. A staffed Town Hall can explicitly balance ordinary year-round crews, using free villagers first and then moving only the minimum necessary labor from strictly lower tiers; equal-priority crews, specialized seasonal/processor labor, builders, and the commanding clerk remain untouched. Separate seasonal controls identify crews stranded at dormant farms, apiaries, vineyards, foragers, and fishing camps, retain one necessary hauler for stored goods or an active cart, and call free labor back when the work window opens. Year-round balancing remains manual; optional seasonal, production, and construction stewards automate only their established safe orders after explicit opt-in.
- **Processor bottleneck diagnostics** — the Town Hall reports the first staffed mill, granary bakery, brewery, smokehouse, or weaver likely to stop from an input shortage or fill its output store. A loaded cart extends runway only when its remaining road travel and unloading time beat the destination's current depletion time; late deliveries stay visible as an avoidable stop. Surplus at one workshop cannot hide a starved or congested branch elsewhere. Each row can center and open the exact site that will fail first. Individual workshop inspectors show the same pressure in cycle coverage and name the limiting input, making road layout, cart throughput, stockpiling, and labor changes directly comparable.
- **Production-stall ledger and explicit crew rotation** — the Town Hall distinguishes staffed output from merely assigned labor across target-governed workshops, stone quarries, hunting halls, and seasonally active fishing camps. It counts sites stopped by truly empty inputs, reached output ceilings, full local yards, depleted sources, or protected wild-stock reserves; incoming matching carts are reported as recovering instead of false alarms, partial processor batches remain productive, and crews with stored goods or active carts retain one dispatcher. One order safely releases blocked workers, while its priority-driven inverse deploys free labor only to capacity-open workshops, source-ready quarries, and hunting halls above their breeding reserve. Generic year-round balancing no longer silently refills these source-bound sites, and no background automation or new save field is required.
- **Bounded parish tithe routing** — each chapel resolves its policy-controlled, road-linked monastery recipient once from the tick’s completed and fire-safe building roster. Every paying household then uses that stable route while the chosen monastery is reloaded by primary key before credit, avoiding a monastery scan and sort for every attendee.
- **Owner-scoped tick rosters** — Sabbath policy and staffed-chapel state are cached once per owner and economy substep, then shared by construction, workshops, carts, gardens, tithes, and household settlement. Chapel discovery uses the shared owner/building-kind index instead of rescanning every building at each pause check; construction invalidates the derived state if a chapel completes mid-substep. Woodcutter sawmill sourcing, well-to-workshop water dispatch, village-storehouse overflow collection, reachable-carpenter cart-speed checks, and nearest-well fire dispatch also draw only their indexed candidate kinds while reloading current rows before selection. Cattle holdings likewise select their bounded priority-field candidates once per owner; each farmstead then reloads only those herds before applying ox power, preserving same-tick health and supply changes without multiplying the full field scan by the number of farmsteads.
- **Settlement HUD** — per-player timber, stone, firewood, water, food, gold, population, housing (occupied/capacity/vacant), free labor, in-game date/time, and live FPS and zoom readout.
- **Cheat mode** — open the game menu, choose any amount up to one billion, and top up every treasury resource for unrestricted city planning and screenshot builds.
- **Shared game balance** — one `balance/gameBalance.json` source generates Rust constants and TypeScript bindings for costs, radii, tick intervals, and production rates.
- **Construction logistics and queue control** — placing a production, storage, service, faith, or trade building creates a cleared construction site, automatically assigns up to four available builders, and reserves its timber/stone cost without teleporting stock. Every site can be held or given low, normal, or urgent priority: urgent work gets first claim on contested carts and scarce stored material, while hold recalls inbound carts, stops hauling and builder work, releases its crew, and keeps the reserved stock earmarked. Resuming a held site automatically reclaims available builders. The server uses four fixed priority buckets rather than sorting the construction queue every tick. Unassigned villagers can fetch reserved materials from any completed, reachable building, so already-produced stock never requires source staffing. Staffed storehouses remain the preferred dispatch points and send substantially larger, faster batches. Recognizable timber/stone carts unload into the intended site, builders advance only as far as delivered materials allow, and the open founding stockyard provides paced off-road bootstrap loads for the first supply chain. The Town Hall aggregates the whole queue and links directly to the highest-priority site that needs intervention.
- **Live building-placement diagnostics and extents** — the existing red placement preview now names the precise blocker while the cursor moves: water, slope, road or parcel overlap, missing local resources, exhausted work extents, unaffordable materials, and civic or frontier prerequisites all use the same messages as a rejected click. Town Hall previews now prove the 24-person threshold, unique civic seat, and a road link to any completed church plus any completed market before turning valid; older landmarks on disconnected parish branches no longer make a viable civic center fail by table order. Guardhouses likewise require their completed watchtower onscreen instead of failing only after a click. Valid footprints receive a distinct ready state, while farms, resource buildings, wells, monasteries, watchtowers, and refuges project their existing work, service, faith, warning, or rally radius as a colored terrain-following ring before commitment; the same terrain-following presentation remains after selection. The status names that extent and retains the current carpenter-adjusted material cost, while valid founding-camp ground returns to its logistics outlook. Client and authority each batch every eligible civic landmark into one pathfinder tree, add no save field, and remove trial-and-error from dense multi-parish planning.
- **Staged construction sites** — foundations, stone courses, timber frames, scaffolding, cut-log piles, and quarried-stone piles update as deliveries and builder work progress. The inspector shows delivered, reserved, in-transit, road access, and builder status. Roads/bridges, backyard structures, site clearing, and demolition remain instant.
- **Building storage** — the village storehouse centralizes timber, stone, and firewood and provides much larger construction-cart batches when staffed; it deliberately does not store food. Each accepted material has a separate collection ceiling, allowing compact local caches or deep central depots without protecting stock from construction and household use. Food stays in capped producer/processor inventories (including fishing camps), in residence need stock after delivery, or in the player treasury as fallback/overflow. Construction spending protects reserved stock from trade and other orders until it is delivered or the site is cancelled.
- **Salvage on demolish** — removing buildings, residence zones, or backyard gardens refunds a fraction of placement cost plus stored resources.
- **Labor assignment** — assign workers to production buildings via the inspector; labor speeds harvest cycles and is capped by available population. A staffed Town Hall can explicitly balance completed year-round services and industries after builders are released, settlers arrive, or priorities change at full employment. High-priority vacancies use free labor first and then draw the minimum necessary workers from strictly lower tiers; equal-tier crews are preserved, specialized labor remains under its own controls, and no future worker is hired or moved automatically.
- **Visible work crews** — staffed gathering and processing buildings claim real household-linked villagers who commute on the settlement schedule. Lumberjacks and lodge woodcutters chop with hatchets, reforesters dig at stumps with shovels, quarry workers mine with pickaxes, foragers gather, hunters check game, fishers work shoals, farmhands and vintners use hoes, herders tend pastures, and well keepers, brewers, smokehouse workers, granary keepers, beekeepers, millers, and carpenters perform job-specific yard work. Builders face incomplete structures and swing hand-jointed hammers. Skeletal work animation is limited to a 64 m viewing radius, with instanced villager LODs beyond it. Randomized work impacts fade out from 12–32 m and are disabled outside the close 32 m camera zoom.
- **Population & housing** — starting population plus occupants from placed residences; settlers arrive gradually per home; unassigned workers form the free-labor pool.
- **Treasury gold** — backyard gardens linked to a marketplace generate village trade; earnings split between **household wealth** (saved per home, capped) and **mayor tax** (Laffer productivity curve). A staffed **chapel** on the road collects flat tithes from household savings when villagers attend.
- **Lumber mill** — harvests the nearest mature tree within a 210 m work extent; stores timber and uses a dry, air-seasoned process rather than an anachronistic water input; up to 3 laborers scale the 9 s harvest cycle.
- **Reforester** — regrows stumps within a 190 m radius through `stump → growing → mature` phases; growing trees render as animated saplings; up to 1 laborer.
- **Stonecutter's camp** — extracts 2 stone from the nearest procedural quarry site within 55 m every 9 s per worker cycle until depleted; stores stone in the building; up to 4 laborers. The world contains one 10,000-stone large deposit and two 4,000-stone small deposits, sized for long-term settlement growth.
- **Woodcutter's lodge** — processes stored timber into firewood on a 5 s cycle, pulls timber from road-connected mills, and dispatches delivery crews along the road network; up to 2 laborers split between processing and delivery. Each lodge can enforce its own settlement-wide physical timber floor, letting a winter-fuel branch burn freely while another protects stock for the next cottage, workshop, or civic project; active construction reservations remain protected independently.
- **Well** — refills groundwater based on local hydrology score, with occasional surges; dispatches visible water carts along connected roads, serving fire calls first, claimed residences second, and then the highest-priority water-starved staffed brewhouse or granary bakery; capacity and yield depend on placement, route length now directly limits industrial throughput, and up to 2 laborers split between drawing and delivery.
- **Hunter's hall** — hunts individual animals from either of the two persistent game habitats within 68 m, stores food, and delivers along roads; up to 3 laborers. One habitat is larger and supports a 20-animal herd, while the standard habitat supports 12. Herds reproduce from survivors, need at least two animals to breed, and migrate when non-hunting buildings disrupt their habitat.
- **Forager's shed** — gathers berries or deep-forest mushrooms within 48 m, stores food, and delivers along roads; up to 2 laborers. Both resources regrow in place during spring and summer and are dormant in winter.
- **Fishing camp** — must stand entirely on dry land with a river fish shoal inside its 64 m work extent. One small and one rich shoal spawn in the water, with visible rigged fish swimming below the surface; their school thins with the authoritative population, occasionally breaks the surface, and plays an out-of-water flop when a nearby catch reduces the shoal. The rich shoal produces 1.75× as much food per harvest. Fish reproduce only in spring from the surviving population; a shoal harvested to zero is permanently extinct. The camp stores up to 120 food and joins normal road delivery claims for residences; up to 3 laborers.
- **Chapel** — parish hub on the road; assign a priest to collect tithes from road-linked household wealth into the **parish coffer** (collect into treasury when ready); boosts settlement, shortage resilience, and abandoned-home recovery. Optional Sunday Sabbath observance (requires a staffed chapel) pauses labor and logistics, while households keep consuming their delivered food, fuel, water, ale, and preserved food. The HUD and Town Hall therefore show how many homes are stocked for the no-cart interval from Saturday night to Monday morning.
- **Pauline monastery** — mid-game hillside landmark (requires staffed chapel and 12+ population); road-linked to the parish for full strength. Autonomous grain→food production, feast-day charity, ongoing food deliveries within a 520 m coverage radius, and wider faith bonuses for road-linked homes inside that radius. Its existing hospitality policy now determines whether apiaries and vineyards stock physical honey and wine here before exporting: supplied hospitality raises chapel-and-market-linked pilgrimage income from 2 to 3.5 gold/day, while disabling it leaves all specialty output for trade. Five fixed feast days create extra reserve draws, and the monastery and Town Hall inspectors show daily runway and annual stock targets. City administration also sets the monastery tithe share (0–80%).
- **Marketplace** — staffed, road-bound village trade hub. Brokers export only treasury goods and stock in road-linked buildings (household provisions and construction reservations stay protected); bulk imports arrive in the market's physical storage for construction carts or household caravans to move onward. Critical households auto-buy only when their full lot fits and their own cart can depart, so busy, resting, or blocked caravans never charge them for somebody else's stock. Ale and cloth, plus honey and wine left after enabled monastery hospitality, are physical export cargo: producers haul surplus to market storage, where broker labor clears the visible queue for gold. These specialties now share a live regional-demand rate: selling continuously depresses it and neighboring demand recovers over time. Each market can sell at any rate, hold below 98%, or wait for 105% favorable demand, trading storage backpressure and delayed guard-pay gold against a better return. Existing saves retain immediate selling. A manual caravan deal occupies one broker, so a two-person desk can keep specialty exports moving. Buy and sell timber, stone, firewood, and food for gold, or barter goods; repeated imports and exports move live regional rates until neighboring caravan routes gradually recover.
- **Expanded agriculture & processing** — arable fields and threshing barns; fields and pastures use flexible convex four-corner boundaries so productive land can fit around roads, terrain, water, buildings, and neighboring parcels. Fields have no hard area cap, with full per-square-metre efficiency through 1,600 m² and soft diminishing returns beyond it; awkward shapes modestly increase work and reduce harvest. Mountain winter rye and locally plausible wheat–rye maslin are tilled and sown in October–November; oats, barley, and fibre flax move that workload to March–April, so rotation redistributes labor as well as moisture and fertility pressure. Barley and maslin join rye and oats in the physical grain chain; pulled flax occupies a separate farmstead fibre store and is carted to the weaver through the existing raw-textile channel rather than inflating food forecasts. Sowing physically consumes grain. Each active field protects enough farmstead stock for its unseeded area and paused fields release that allocation; granaries can cart seed back to a short farmstead, while every new holding arrives with enough seed for roughly one efficient field. If a settlement loses its last seed, a staffed marketplace can import one physical 24-unit seed-grain sack at a scarcity-sensitive regional price; a free granary or staffed marketplace then sends a physical cart to the least-covered reachable staffed holding instead of creating an abstract treasury refill. Each farmstead forecasts September grain and fibre harvests, spring and autumn work, seed shortfalls, separate onsite rooms, and exportable grain. Partial harvests remain credited when storage or hauling blocks the crew, while mature crops still pay their fertility cost at the October deadline. The chain continues through a river **watermill** (shore placement), staffed **granary**, **brewery**, **smokehouse**, and **weaver**. Grain centralized at a granary remains usable: staffed granary keepers send one physical cart to the operational processor in the highest selected work-priority tier, then choose its lowest cycle runway, road distance, and stable building order instead of whichever workshop happens to tick first. If that priority-selected processor is below one full cycle, it preempts ordinary food duty; in contested worlds it shares that emergency slot with armed guardhouses below three food-days. Multiple granaries skip a workshop or company that already has supplies inbound. Every granary can set a strategic grain floor; routine processors and any foreign grain commitment stop at that floor, while a linked seed-short farmstead may deliberately draw through it to finish sowing. Farm carts first retain linked-field seed, then use the same processor priority and runway rule, centralize the remaining crop in a granary, and overfill workshop warehouses only when no granary can receive it. Each granary can prioritize current household food deliveries or winter preservation and independently choose a 25%, 50%, 75%, or 90% fresh-food intake target; smokehouses receive central food through that source-side choice instead of pulling a cart ahead of it, and a blocked first duty immediately falls through to the other. Institutional fresh-food intake centralizes only true supplier surplus: every source first protects one normal food cart per claimed household, capped at half its storage, before granaries, smokehouses, or guardhouses may load. Remote branches therefore keep a local buffer while unclaimed harvests can move entirely into sheltered storage or preservation. Forest **apiaries** require mature-tree forage and produce from April through September; hillside **vineyards** concentrate production in the September–October grape harvest.
- **Crop-specific field silhouettes** — rye keeps tall pale awned ears; oats branch into drooping panicles; barley carries compact heads with very long awns; wheat–rye maslin is shorter and plumper; flax grows slender green stems under blue blossoms. Every crop rises from varied terrain-hugging worked earth, shifts toward harvest color with maturity, and leaves an irregular cleared band and stubble as workers advance. Worked fallow grows low volunteer cover instead of masquerading as grain. A deterministic close/overview/crop-roster showcase lives at `farm-field-lineup.html`; the reference feature audit is in [Farming reference parity](docs/FARMING_REFERENCE_PARITY.md).
- **Mixed husbandry with physical manure logistics** — cattle provide dairy, collectable farmyard manure, and ox power; sheep fit steeper uplands and provide cheese and wool income; woodland pigs depend on mature pannage trees. A healthy, supplied cattle herd supports only the two highest-priority fields inside its work extent, cutting their ploughing labor. Fertility is no longer a free proximity effect: supplied cattle accumulate dung-and-bedding stock at their holding, winter housing improves collection, and the holding’s single road cart serves the least-covered crop farmstead after its food duties. Farm workers consume that physical stock in proportion to ploughing progress, so partial coverage grants only a partial soil benefit and field priority determines which parcel receives scarce manure first. Both holdings expose fill-and-clear manure piles, the cart carries a distinct visible load, and field, farmstead, and Town Hall ledgers show spread, onsite, inbound, and shortfall values. Cattle and sheep holdings can reserve 0%, 35%, or 60% of June–August pasture for hay: more meadow raises a local, capped winter loft reserve but immediately reduces summer grazing, while drought lowers the cut. Winter herds consume that hay before emergency grain. Each holding also has a winter breeding-reserve policy: keeping more animals accelerates future growth but consumes pasture and fallback fodder, while surplus above the reserve is actually removed and converted into storable food during October–November. From September onward, staffed holdings cart seed- and reserve-safe grain toward the remaining 30-day deficit after hay while retaining a two-cycle emergency buffer; holding and Town Hall forecasts expose meadow pressure, loft capacity, shortages, and sites that still need mid-winter resupply. Slaughter waits for labor and enough room for the whole animal’s yield, so smokehouse placement, autumn logistics, and road reliability matter.
- **Carpenter & wheelwright** — a staffed workshop gives every site on its road component a 10% timber discount and makes carts departing connected origins travel 18% faster. Placement previews show the contextual discounted cost, planned delivery timers include the cartwright bonus, and the workshop inspector reports whether support is active. In contested worlds it also turns 2 timber plus 1 unit of road-hauled imported ironwork into a polearm; a staffed marketplace buys 6 iron heads and fittings for 12 gold, then physically dispatches them to the carpenter. Frontier industry remains available when enemy pressure is set to zero, so players can plan and drill without enabling raids. **Ferry landing** (shore placement) earns trade income when staffed and marketplace-connected.
- **Road-based logistics** — Dijkstra road-path distance routes construction materials, timber mill→lodge, specialist inputs between processors, well→workshop water, and household provisions. Construction haulers preserve the storehouse/specialist source hierarchy, then choose the shortest reachable road haul inside the winning class instead of trusting straight-line proximity; bounded priority buckets avoid sorting every stocked building. Storehouse overflow carts stop at each material's selected collection ceiling, turning depot placement and stock distribution into an explicit network choice instead of letting one warehouse absorb every producer surplus. Production chains likewise prefer the nearest reachable stocked source, unfinished buildings reject specialist cargo, and each processor accepts one inbound haul at a time. Because a supplier can launch only one cart, source and destination selection is one-pass rather than sorting every reachable building; mill routes no longer build full path polylines just to compare distance. The nearest eligible stocked supplier claims each home for routine food, ale, and preserved-food service, so an empty winter apiary, vineyard, brewhouse, or smokehouse immediately yields to a stocked branch; firewood and water retain capacity-based service claims. Each server cart selects its next home in one pass by lowest per-person runway, then shortest route. Wells preserve that household priority before selecting the highest work-priority workshop, then the lowest water stock ratio, shortest route, and stable building order in one pass, so compact service territories and industrial clustering matter without whole-branch sorting stalls.
- **Delivery trips** — server-spawned road agents travel outbound, unload at the residence or receiving workshop, and return; client renders worker-hauled wooden carts with recognizable commodity loads such as bundled firewood, water barrels, food baskets, sacks, kegs, amphorae, timber poles, quarried stone, iron fittings, and bundled polearms.
- **Persistent wild-resource ecology** — procedural game habitats, forest-edge berry patches, deep-forest mushroom beds, and water-bound fish shoals are bootstrapped once. Harvesting reduces current stock without replacing the node: plants recover seasonally, fish reproduce in spring, and game reproduce continuously above their two-animal breeding floor.
- **Wild-stock reserve policy** — each hunter's hall and fishing camp can protect 0%, 25%, or 50% of every population's carrying capacity inside its work extent. A reserved population rests while workers can switch to another healthy habitat or shoal in range, turning immediate food output into an explicit extinction-risk and recovery-speed tradeoff. Existing saves default to open harvest.
- **Tree lifecycle** — server-driven `mature → stump → growing → mature` phases with client visual sync (instanced forest, animated saplings, stumps).
- Server-authoritative simulation tick (200 ms) in the Rust module — buildings, trees, quarries, foraging, delivery trips, residence needs, backyard gardens, and settlement growth all run server-side. Player-facing Pause/1×/4×/8× controls keep every system synchronized; Pause stops authoritative state changes before any simulation work begins.
- **In-game calendar and seasons** — fixed 30-day months, twelve months, no leap years or drift, and a 5-minute day at 1× speed. Spring rain and ecological recovery, summer droughts, September harvest, autumn sowing, and winter heating/dormancy all affect authoritative simulation systems. See [Seasons, calendar, weather, and simulation speed](docs/SEASONS_AND_TIME.md).
- Construction dock UI — `R` for roads, `B` for settlement essentials (residences, well, chapel, monastery, marketplace, ferry), `V` for industry and provisioning (grain chain, food processing, forestry, extraction, carpenter, apiary, vineyard), `M` for the hydrology overlay. **City administration** (main menu → gear) sets mayor tax, parish coffer policy, and Pauline monastery tithe / hospitality policy.
- Building placement tool with terrain-following preview, flattened terrain pads, functional extent overlays for spatial buildings, and validation (water, slope, overlap, trees, quarry stone, and foraging nodes). Buildings may be constructed without road access; roads are connected afterward to enable transport, services, and other network-dependent bonuses.
- Building and residence demolish actions from the inspector panel.
- Click-to-inspect resource panel for quarries, foraging nodes, buildings, residences, backyards, and river access — yields, storage, labor controls, runway days, delivery status, and hydrology grades.
- Map icons at zoomed-out camera levels for quarries, foraging nodes, and backyard gardens; click an icon to inspect the site.

### Residences

- **Residence zone placement** — click two points along a road for the frontage edge, then a third point behind the road to set backyard depth; the plot subdivides into residence parcels.
- **Residence layout HUD** — adjust plot count (+/−), rotate frontage edge (`F`), and see validity while placing.
- **Road frontage requirement** — zones must sit within frontage distance of the road network; parcels face the selected frontage edge.
- **Learnable residence progression** — each residence costs timber and stone on placement; narrow and wide parcels get 2 or 4 population capacity respectively (default 3). Tier 1 households need only food and receive a long shortage grace period. Tier 2 adds firewood and water; tier 3 adds preserved food, ale, cloth, and slowly replaced pottery, with increasingly strict shortage pressure and road-linked supply requirements. Before upgrading, the residence inspector audits each required service route and the available timber, stone, and gold, disables blocked upgrades, and distinguishes a valid but temporarily empty workshop from a missing route. A tier-2 water route must fall inside the well's physical service radius as well as share a road branch, preventing upgrades into homes that can never receive water.
- **Gradual settlement** — empty homes fill one settler at a time after a settle timer; inspector shows pending settlers and ETA.
- **Procedural residence meshes** — timber-and-stone houses with varied facade and roof colors per parcel; instanced fence posts and rails along zone boundaries.
- **Residence needs** — residents consume firewood, water, and food per person per tick; homes track per-need stock and deficit timers server-side.
- **Abandonment & recovery** — prolonged shortage of any need abandons a residence (population drops to zero); homes can recover once all needs are restocked and road-connected suppliers are available.
- **Backyard gardens** — click an occupied home's backyard to plant apple/cherry orchards, vegetable gardens, flower beds, herb plots, or a hen yard. Vegetable plots visibly divide into historically plausible cabbage, carrot, and turnip beds, with a rear bean-and-pea trellis; generated botanical cutouts supply veined cabbage leaves, feathery carrot tops, and broad turnip rosettes around modeled heads and roots. Food plots partly supply their household; surplus and ornamental goods sell only through a completed marketplace on the same road branch. Output follows the 06:00–20:00 workday, seasonal crop windows, drought, and an observed Sunday Sabbath: orchards deliver a concentrated September crop, annual beds go dormant in winter, and hens retain 75% winter output. After-tax profit builds **household wealth**, while tax actually collected by the available Town Hall clerk flows to treasury. Planted gardens render as small 3D plots behind each home and let the underlying terrain provide natural ground cover.
- **Household economy** — each occupied home tracks saved gold (`household_wealth`, capped); residence and backyard inspectors show wealth, current-condition food and garden income, market route, collection loss, and parish tithe exposure. City administration and the Town Hall summarize current routed activity, household income, collected tax, and the 120-day seasonal/road outlook instead of presenting a permanent fair-weather daily rate.
- **Residence inspector** — firewood/water/food stock, runway days, household wealth, operational firewood/well/food suppliers, upgrade readiness and blockers, chapel link, road access, settlers pending, and demolish options for a single home or entire zone. Routine food carts from gatherers, granaries, apiaries, vineyards, livestock holdings, and parish-linked monasteries share nearest-road territories; paid household orders and parish relief deliberately bypass routine priority and serve their intended home first.

## SpacetimeDB (authoritative backend)

This project uses [SpacetimeDB 2.0.1](https://spacetimedb.com/) for authoritative game state: treasury, buildings, trees, quarries, foraging nodes, roads, residence zones, backyard gardens, delivery trips, and the full settlement supply chain. The client is a thin renderer — all economy simulation runs in the Rust module via a scheduled `tick_sim` reducer every 200 ms.

### Run locally

1. Start the SpacetimeDB standalone server (once per machine):

```bash
spacetime start
```

2. Publish the Rust module and regenerate TypeScript bindings:

```bash
npm run deploy:local
```

This runs `generate:world-bootstrap` (tree and foraging layout data for server bootstrap), `generate:game-balance` (shared economy constants), publishes the module to database `city-builder`, and writes TypeScript bindings to `src/generated/`.

To wipe and republish from scratch:

```bash
npm run deploy:local-clean
```

3. Start the Vite dev server:

```bash
npm run dev
```

The client connects to `http://localhost:3000` with database name `city-builder`.

### Anonymous identity

No login is required for local dev. On first connect SpacetimeDB issues a signed JWT; the client stores that token in `localStorage` (keyed by database name) and reconnects with the same player identity on refresh. Treasury, buildings, roads, and residences are scoped to that identity.

When real auth is added later, swap the token source in `src/network/identityPersistence.ts` — the connection layer stays the same.

**Player reducers:** `place_building`, `demolish_building`, `assign_building_labor`, `set_harvest_reserve_percent`, `set_guardhouse_muster_post`, `set_seasonal_labor_steward`, `set_production_labor_steward`, `set_construction_labor_steward`, `set_labor_steward_reserve`, `set_pottery_dispatch_policy`, `collect_chapel_coffer`, `marketplace_trade`, `cancel_marketplace_trade_order`, `set_marketplace_gold_reserve_target`, `set_marketplace_seed_grain_target`, `set_marketplace_iron_target`, `set_marketplace_salt_target`, `set_marketplace_ironwork_target`, `set_economic_activity_tax_rate`, `set_chapel_parish_policy`, `set_monastery_policy`, `reset_world`, `configure_world`, `place_backyard_garden`, `demolish_backyard_garden`, `sync_road_network`, `remove_road_edge`, plus place/demolish/upgrade residence zone. **Bootstrap reducers:** `bootstrap_quarries`, `bootstrap_trees`, `bootstrap_foraging`.

### Server connection required

Medieval Settlement is **not playable without a live SpacetimeDB connection**. The client renders replicated server state; it does not queue roads, buildings, or economy actions offline.

- **Boot** — the loading screen stays up until SpacetimeDB connects, subscribes, and world bootstrap completes. If the server is down, you get a retry screen instead of partial gameplay.
- **Mid-session disconnect** — all construction tools are disabled and a reconnect overlay appears with automatic retry.
- **New world** — requires a live connection; `reset_world` must succeed on the server before local settings and identity are cleared.

See `docs/design/server-authoritative-connection.md` for the full connection model.

## How It Works

The terrain is generated as a continuous heightfield in `src/terrain/Terrain.ts`. It combines several value-noise layers with broad sine/cosine shaping, then uses vertex colors to blend grass tints and a shore-blend attribute for muddy river banks. `TerrainGrassMaterial.ts` builds a TSL node material that samples meadow, dense, and dry PBR sets per vertex.

`RiverLayout.ts` generates procedural river corridors from map edges toward a central drain, with optional tributaries. `RiverField.ts` rasterizes those corridors into mask and signed-distance fields used for terrain carving, shore mud blending, and prop blocking. `RiverWaterMesh.ts` runs a lightweight 2D virtual-pipes water simulation each frame and drives animated foam and shore effects through `RiverWaterMaterial.ts`. `HydrologyOverlay.ts` reuses the river field to visualize groundwater scores for well placement.

`QuarryLayout.ts` always places one rich rock deposit and adds ordinary deposits from the map-size and abundance budget, carving pit depressions into the heightfield and scattering instanced boulders via `QuarrySystem.ts`. Quarry yields and remaining stone are tracked server-side in the `quarry` table. Wild-resource nodes (game, berries, mushrooms, and water-bound fish shoals) scale with map size and abundance; regional variety deterministically omits some families unless the player requests a complete region. Game remains the winter-available safety net, while farms, wells, and managed woodland are universal so a specialized roll encourages marketplace trade without making the settlement nonviable. Generated nodes are bootstrapped from `world_foraging.json`; `foraging_respawn.rs` advances their persistent lifecycle rather than deleting or rerolling them. Berry fruit and close-zoom mushroom models vanish as stock is gathered and return in the growing season; deer actors disappear one-for-one as hunters kill them and move with a migrating habitat.

Road placement is handled by `src/roads/RoadTool.ts`. Pointer input is projected onto the terrain by `TerrainProjector`, collected as clicked road nodes with optional wheel-adjusted curvature, validated against slope and minimum length rules, and committed into a `RoadNetwork`.

`src/roads/RoadNetwork.ts` stores roads as nodes and edges. It resolves endpoint snapping, splits existing road segments when new paths connect into them, detects crossings, prunes orphan nodes, and classifies junction types.

`src/roads/RoadMeshBuilder.ts` turns road graph edges into terrain-following ribbon meshes. It samples Catmull-Rom curves, builds a core dirt ribbon, adds irregular blended shoulders, and keeps the road slightly above the terrain to avoid z-fighting. When a path crosses water, `RiverBridgeSpans.ts` detects wet runs, raises the deck above the water surface, and blends graded approach ramps; `BridgeSupports.ts` places instanced posts under the deck. `RoadJunctionBuilder.ts` adds endpoint caps and junction patch geometry at classified nodes.

`RoadPlacementValidation.ts` checks slope, minimum length, max bridge span, and rock collisions before commit. `RiverShoreCrossingGaps.ts` seeds procedural clearance zones along river banks so shore stones skip natural crossing points.

`src/props/ForestProps.ts`, `ForestUndergrowth.ts`, and `ForestManager.ts` scatter instanced conifer trees, bushes, ferns, and rocks across the playable area. Roads automatically clear trees and undergrowth but remain blocked by loose boulders, preserving meaningful route planning. Building pads and farm fields prepare their sites by clearing vegetation and overlapping loose rocks; construction also deletes tree entities inside the authoritative building footprint without granting free timber. `RoadStumps.ts` places cut stumps along road shoulders after clearance. `RiverReeds.ts` adds instanced reed clusters along river banks. `ForestVisualSync.ts` mirrors server tree phases (`stump`, `growing`, `mature`) onto the instanced forest — growing trees swap to animated sapling meshes via `TreeSaplings.ts`.

`src/buildings/BuildingTool.ts` handles placement of all production, faith, and trade buildings. `BuildingPlacementValidation.ts` rejects water, unsuitable slopes, overlapping footprints, and missing local natural resources where a building fundamentally depends on its site. Shore buildings use dense bank sampling so narrow rivers are recognized reliably. Placement creates an inert construction site: `ConstructionSiteMesh.ts` stages foundations, scaffolding, frames, and material piles while `server/src/simulation/construction.rs` reserves spendable stock, lets unassigned labor fetch it from any completed reachable source, prioritizes staffed storehouses for high-capacity cart dispatch, handles the founding reserve, and gates builder progress by delivered materials. Road access is not a placement prerequisite, so a waiting site can be connected afterward. `BuildingTerrainLayout.ts` prepares the site immediately, and demolition/cancellation is immediate as well.

`src/residences/` handles residence zone drawing — a frontage edge snapped to the road network plus a depth point defining the rectangular plot. Layout and placement validation subdivide the zone into residence parcels and enforce road frontage, depth limits, overlap checks, and resource costs. `ResidenceMarkers.ts` and parcel fencing render procedural houses along zone boundaries. Placement calls the residence-zone reducer; the server creates residence rows with population capacity scaled by parcel width. `residence_settlement.rs` gradually fills homes; `backyard_garden.rs` runs garden production and treasury tax.

`src/logistics/` mirrors server delivery logic on the client for inspector displays — runway days, trip durations, lodge/well/food-supplier targets, and residence needs status. The server evaluates stock and road distance once per eligible destination and selects only the next stop instead of sorting every claimed branch; an explicit paid-household or parish-relief target wins before routine runway priority. Industrial water uses the same physical trip table and cart renderer as household supply: processors consume only water already unloaded into their own store, while inspectors show inbound carts and stored cycle coverage. `DeliveryAgentRenderer.ts` animates replicated `delivery_trip` rows as wooden carts along the road network, with rigged villagers walking at the handles and keeping their hands planted through a lightweight IK pass. `src/roads/roadConnectivity.ts` and `server/src/roads/network.rs` compute Dijkstra road-path distances for building access and supplier routing.

`src/placement/` maintains a spatial index of building, residence zone, and road footprints for fast overlap checks during placement.

`src/grass/GrassBladeField.ts` streams instanced 3D grass tufts in camera-relative chunks. Tufts fade in at close zoom (aligned with the terrain dirt LOD band) and are cleared near committed roads. `TerrainRoadWear.ts` updates a per-vertex `roadWearBlend` attribute so the TSL grass material tints to packed dirt along road corridors.

`src/data/spacetimeGameStore.ts` subscribes to replicated tables and maps rows into client `GameState`. Before the scene exists, startup probes `world_config` and adopts any configured server generation contract; browser storage is only a fallback when that probe is unavailable. `GameRuntime.ts` then connects, verifies that the finished terrain still matches the current server row, publishes settings for a new world via `configure_world`, bootstraps quarries, trees, and foraging from the client layout, and hydrates the road network from the server snapshot. A late authority race is surfaced once and requires a reload instead of retrying every replicated tick. Module `init` still seeds deploy-time embedded JSON so a fresh publish has world entities before the first client connects; `bootstrap_*` reducers apply client-authored rows only and no longer fall back to that JSON when empty arrays are sent. `reset_world` clears settlement progress and global entities but does not re-seed deploy-time defaults — the next connect re-publishes settings and re-bootstraps from the authoritative layout.

On the server, `server/src/reducers/simulation.rs` runs each 200 ms tick: construction reservations/hauling/builder work, wild-resource lifecycle and habitat migration, lumber mills, reforesters, quarries, lodges, wells, hunter's halls, forager's sheds, fishing camps, the grain→food processing chain (fields, barn, watermill, granary, brewery, smokehouse, apiary, vineyard), monastery charity/hospitality/pilgrimages, market-imported iron, charcoal-fired smithing, physical civilian-tool maintenance, carpenter polearms, guardhouse readiness/upkeep, ferry income, `delivery_trips.rs` road agents, progressively tier-gated residence needs, backyard gardens, chapel tithes, and settlement growth. Fresh food is physically held by producer buildings, homes, smokehouses, monasteries, marketplaces, granaries, and guardhouses and spoils continuously according to season, weather, and storage quality. Firewood, water, routine food, ale, and preserved-food suppliers each claim one nearest-road household territory; those maps are built lazily once per owner and need per simulation tick, preventing overlapping carts without repeating whole-settlement path searches for every supplier. Paid marketplace orders remain an explicit emergency override. Cached food-territory counts protect a local delivery reserve at every claimed source before any institutional pull or producer-pushed food cart is loaded. Apiaries and vineyards keep that household food priority, then use the shared monastery policy to route honey or wine into the nearest linked hospitality store with room before falling through to a marketplace; policy reads are cached once per owner and simulation substep. Smokehouses receive granary stock only through the granary's selected household/preservation order, while armed guardhouses below their three-day floor enter the same source-side critical-cart arbitration as starved grain processors; this removes building-iteration order from central food policy. Farm seed protection performs one owner-wide field pass per simulation substep and updates the affected holding after field work. Seed distribution then scans short holdings once per free granary or staffed market, picks one least-covered road-reachable claim without sorting the branch, and rejects destinations already receiving grain; the work therefore scales with actual seed sources instead of repeating a source search from every farmstead. A lazy per-tick owner/building-kind index now supplies construction-material, grain, guard, processor, market, parish, firewood, water, and territory candidate rosters from one building-table pass per substep. Construction receives the initially stocked source IDs—material stock can only shrink during that phase—and every candidate ID is resolved through the primary key before selection, preserving current stock, staffing, completion, fire, and inbound-cart state. Sunday schedule checks share one indexed Sabbath-policy read and one derived staffed-chapel result per owner and substep instead of repeatedly scanning the whole settlement; chapel completion invalidates that owner’s derived result before later phases. Immutable road snapshots are parsed and indexed once per scheduler heartbeat, then shared by delivery movement and every economy substep while their mutable caches remain isolated. Idle fire ignition combines five exact per-tick probabilities into one one-second structure scan; burning, damage, response, and spread still advance every substep, using one occupied-target set instead of repeated incident queries. The remaining economy shares one lazy disabled-target set, while chapel and monastery IDs ride the normal building classification pass instead of triggering two more whole-table scans. Labor reconciliation now runs only when population is actually removed; a returning owner receives one connection-time repair for legacy or interrupted saves instead of paying a settlement-wide allocation scan on every economy substep. Unstaffed processors neither request inputs nor dispatch provision carts. Incomplete buildings are excluded from production, services, bonuses, trade, and policy gates. Economy constants come from `balance/gameBalance.json` via `balance_generated.rs`.

`src/resources/ResourceInspector.ts` provides the settlement HUD and click-to-inspect panel for quarries, foraging nodes, buildings, residences, backyards, and river access — including labor assignment, grain-work priority, demolish actions, hydrology grades, and delivery status. `WorldQueries.ts` resolves inspectable targets from terrain clicks. `src/map/` projects quarry, foraging, and backyard icons at zoomed-out camera levels.

`src/camera/CameraController.ts` drives the RTS orbit camera with smooth pan, rotate, and zoom (displayed as a percentage in the HUD). `FirstPersonController.ts` handles walk mode — pointer-lock look, terrain- and road-deck-sampled foot placement, sprint/jump/crouch, free-look, camera bob, and compass heading publication.

`src/ui/BuildToolbar.ts` composes the construction dock, illustrated build menu, settlement HUD, contextual tip cards, FPS/zoom stats, compass strip, residence layout HUD, delete popup, and game menu. `ToastManager.ts` surfaces placement validation errors. `LoadingScreen.ts` shows staged progress during world bootstrap. `AmbientAudioController.ts` crossfades wind and village ambience based on camera distance to your buildings and residence zones.

`src/scene/SceneManager.ts` owns the renderer backend, terrain, sky, forest, grass field, river system, quarry system, hydrology overlay, road groups, delivery agents, selection/preview groups, lighting, fog, and post-processing. Forest and grass build asynchronously after the first frame to keep initial load responsive.

## Development Notes

- Road editing works offline; buildings, residences, and economy require a running SpacetimeDB server (`spacetime start` + `npm run deploy:local`).
- `npm run build` runs TypeScript first, then Vite's production build.
- `npm run deploy:local` regenerates world bootstrap data and game-balance constants, publishes the Rust module, and refreshes `src/generated/` bindings — run this after any server schema, reducer, or balance change.
- `npm run generate:game-balance` regenerates `server/src/balance_generated.rs` and `src/generated/gameBalance.ts` from `balance/gameBalance.json`.
- `npm run test` / `npm run test:ci` run the TypeScript contract-test suite (`scripts/run-all-tests.mts`).
- `cargo test` in `server/logic/` runs host-side Rust unit tests for pure simulation/economy logic. The WASM module crate itself cannot link native `cargo test` binaries.
- `npm run test:e2e` / `npm run smoketest` run the Playwright smoke path: connect to SpacetimeDB, open the build menu, place a reforester, and assert the settlement HUD timber drops. Requires `spacetime start`, a published `city-builder` database (`npm run deploy:local`), and Playwright Chromium (`npx playwright install chromium`).
- GitHub Actions CI runs contract tests, client build, `cargo check`, `cargo test`, and the browser smoke job against a local SpacetimeDB instance.
- `npm run test:lodge-logistics` runs a standalone script validating firewood delivery routing logic.
- `npm run test:fishing` validates fish world placement, dry-land camp placement, storage, residence food claims, icon treatment, finite population harvesting, protected-stock caps, spring reproduction, winter freeze, extinction, population-scaled school visuals, and the rigged swimming/flop animation asset.
- `npm run test:foraging-ecology` validates mushroom world placement and deep-forest bias, seasonal policy, forager compatibility, wild-stock reserve parity, persistent lifecycle wiring, herd visuals/migration, and granary collection.
- WebGPU is attempted first; if initialization fails or the browser lacks support, the app falls back to WebGL automatically.
- Production build splits Three.js, SpacetimeDB bindings, and vendored vegetation/sky code into separate chunks to keep the main entry bundle smaller.
- Forest and grass vegetation build asynchronously after the first frame to keep initial load responsive.
- `window.__medievalGameState` exposes dev helpers for inspecting live client state in the browser console.
- `dist/`, `node_modules/`, logs, and local editor files are ignored by Git.
